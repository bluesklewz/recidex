### B. Library ring — geometry / camera / focus (pmnd.rs-style)
Everything below is in the **R3F module island** (`<script type="module" async>` near end of `<body>`).

- **Card orientation:** each card is now **tangent to the circle** — `rotation.y = angle − 90°`
  (the `−` sign was chosen so side segments present their faces; the front/back arcs go edge-on).
  This is the "fanned stacked-slat / Rolodex" look. Card plane changed portrait `1.6×2.0` → **4:3
  landscape `CARD_W=2.0, CARD_H=1.5`** (to match the DOM `.rv-flip` card — see D).
- **Camera:** new `Rig` component owns the camera every frame — elevated + oblique base framing
  (`CAM_BASE (0, 7.6, 16.4)` → `CAM_TARGET (0, −1.6, 0)`, fov 40, `lookAt` each frame) so the whole
  ring reads as an ellipse (near + far arcs both in frame).
- **Cursor parallax:** a `pointer` ref (window `pointermove`) → subtle camera azimuth (`PARALLAX_AZ
  0.13`) + elevation (`PARALLAX_EL 2.0`) swing, additive to the wheel-driven scroll rotation, zeroed
  during the morph.
- **Hover preview:** `CenterPreview` renders a **duplicate** of the hovered card at a fixed point in
  the ring's opening (`PREVIEW_POS`, billboarded, fades/scales in). **The original card never leaves
  its slot** (the earlier "fly to center" behaviour was reverted — it moved the click target).
  Hover is R3F raycast `onPointerOver`, cleared on a 320ms debounce.
- **Category labels:** `CatLabel` — one billboarded text plane per segment (`Appetizer` / `Entree` /
  `Dessert` / `Drink` / `Seasoning`), child of the rotating group (orbits with the ring) but
  **yaw-only billboarded** so it stays upright rather than tipping with camera pitch. Canvas-texture
  text (`labelTexture`), tint colour.
- Blank `PAPER_BACK` reverse on each card (far arc reads as the back of a donut). Deliberately NOT
  the graph.

### C. Ring ⇄ recipe morph (the cards travel; no hard route cut)
- `anim` module-global state machine + `easeInOut`. `RecidexLibrary.exitToRecipe(id, peerIds)` →
  `anim.phase='toRecipe'`; over `MORPH_MS` (720ms) every `Card` blends **in world space, then back to
  local** from its ring slot to its `carouselSlot` (selected → `CAROUSEL_ORIGIN` forefront, peers →
  vertical depth stack, non-peers recede + fade), while `Rig` blends `CAM_BASE`→`CAM_RECIPE`.
- `exitToRecipe`'s promise is **rAF-driven** — resolves when `anim.raw >= 1`, not a bare timeout, so
  the frame is genuinely settled before the snapshot.
- **Reverse:** `viewLibrary` reads `sessionStorage['recidex-morph']`, passes `resume={selectedId, yaw,
  peers, hold}` to `mount` → `anim.phase='toRing'`, cards start in the stack and morph home, scroll
  resumes from the saved yaw so the ring looks exactly as it did before selection. `resume.hold`
  offsets `anim.start` into the future to freeze the carousel layout while the DOM freeze-frame
  cross-fades out.
- `viewNew` clears a stale `recidex-morph` so a `/new` detour can't misfire the reverse.

### D. Card parity (WebGL card = DOM flip-card front)
- `cardTexture(recipe, big)` was fully rewritten as a **pixel port of `labelFace`** (the DOM
  flip-card front): chocolate-bar label — tracked Chathura title, red `batchNo()`, yield row,
  `TOTAL TIME` / `dietLine()` row, `INGREDIENTS` (quantities stripped via `ingShort`, 3-line clamp),
  ✦ ringed stamp, wavy `--paper-edge` rules, dog-ear, faint grain. No border rect, no orange
  category eyebrow, no bracket motif (all removed).
- `batchNo` / `dietLine` / `ingShort` are **re-implemented in the module** (the IIFE copies aren't
  reachable across the script boundary).
- **Why:** the freeze-frame handoff (E) only looks convincing if the WebGL card and the DOM card are
  the same design. Verified aligned at 1440×900: projected card rect vs DOM `.rv-flip` rect =
  **Δcenter 0/−3px, scale 1.005×** (tuned via `CAROUSEL_ORIGIN = (−1.08, 0.2, 3.1)` and the selected
  `carouselSlot` scale `1.05`).
- The card **back** is still the blank `PAPER_BACK` (far arc only) — porting the graph to the back
  is an explicit non-goal.

### E. Freeze-frame handoff (`HANDOFF_MS = 240`)
Replaces the old plain `.lib-stage-out` canvas fade.
- **Forward:** `openRecipe` → after the morph, `RecidexLibrary.snapshot()` returns
  `{ url: <canvas>.toDataURL('image/png'), rect: <selected card screen box, projected analytically
  through a temp CAM_RECIPE camera `_projCam`> }` (needs `gl.preserveDrawingBuffer:true`, which was
  added to the `<Canvas>`). Stashed in the IIFE var `pendingSnap`.
- `render()` floats `#recidex-snap` (that full-frame PNG, `z-index:58`, `pointer-events:none`) over
  the incoming view and **tears the canvas down immediately** (snapshot carries its pixels).
- `viewRecipe(root, id, snap)`: skips the `.rv` `rvEnter` fade (`grid.style.animation="none"`),
  nudges `.rv-stage` so the real forefront card starts exactly under the snapshot then eases home
  (only if the residual delta exceeds thresholds — usually it doesn't), and `dissolveOut`s
  `#recidex-snap`.
- **Reverse:** `render()` reparents the live `.rv` + `.rv-crumb` into a fixed `#recidex-rv-freeze`
  (`z-index:6`, with the page-ground radial gradient as bg), then `viewLibrary` mounts R3F under it
  with `resume.hold` and `dissolveOut`s the freeze.
- Helpers: `teardownStage`, `dissolveOut(node, delay, dur, after)`.

### F. Delayed right-column entrance (recipe view)
- On `viewRecipe` mount the text column is held at `opacity:0` and then does a light **staggered
  cascade** (`@keyframes rvColIn` — opacity + `translateY(11px→0)`, 380ms, `--ease-liminal`):
  `.rv-title` (0) → `.rv-desc` (+72ms) → Instructions+Notes block (+144ms) → `.rv-tags`+`.rv-actions`
  (+216ms).
- **Trigger:** keyed off **"the card finished arriving"**, not a fixed timeout — a poll loop that
  waits for *both* `#lib-stage` and `#recidex-snap` to be gone from the DOM (+ ~175ms), with a 1.6s
  safety cap. Deep-links use a double-rAF fallback. `prefers-reduced-motion` → column just appears.
- The card and the left `.rv-labels` list are **excluded** (card = handoff; labels = chrome).
- If `paintDetail` repaints (carousel step) before the cascade fires, the fresh elements are re-hidden
  so they join the cascade instead of flashing.

## 4. Durable decisions this session

1. **Chathura `line-height: 0.6`** (unitless) is the house value now — Chathura carries its own
   vertical air; `60` in the QA request meant the ratio, not px.
2. **Section titles = 36px** on the recipe view (`.rv-sec-h`), scoped there — the design-system
   `display-lg` token is unchanged.
3. **Ring cards are tangent** (`angle − 90°`), **4:3 landscape**, and their texture is a **pixel port
   of `labelFace`**. The ring card and the DOM carousel card must stay identical — the handoff
   depends on it. If you change one, change the other and re-check the projected-rect alignment.
4. **The morph/handoff is one continuous motion, not two views.** Forward: cards morph → snapshot →
   route → DOM view under a dissolving freeze-frame. Reverse: freeze the live DOM → mount R3F under it
   → dissolve → morph home. Never reintroduce a hard route cut here.
5. **Transition triggers key off DOM state, never fixed timeouts** measured from an earlier event —
   the column entrance waits for `#lib-stage` + `#recidex-snap` to be gone; `exitToRecipe` resolves
   on `anim.raw >= 1`. This survives timing changes.
6. **Two module islands** now (`RecidexLibrary`, `RecidexExport`), both via the import map, both
   `window.*`-exposed. Still no bundler, still no build step. Don't add a third without a reason.
7. **Red-as-danger is allowed once**, on the edit form's `.btn-del` (no batch numerals there → still
   one red per viewport). This is the only exception to the design system's "red is never state/danger".
8. **`CAT_LABEL` is duplicated** (IIFE + module). Accepted cost of the script boundary. Keep synced.
9. **No PNG-only export** anymore — Export is a real PDF/JPEG menu targeting the **graph** (not the
   label face). The old `exportCard()`/`fitGraph()` stay deleted.
10. **`brand_assets/Recidex Design System.dc.html` was left untouched** — only `design-system.html`
    was in scope for the QA pass.

## 5. Dead ends / gotchas

1. **Headless Chrome fast-forwards CSS transitions between forced paints.** You cannot screenshot a
   mid-crossfade / mid-cascade / mid-morph frame — every screenshot jumps the animation clock to
   ~done. Verify with element-state sampling (`getComputedStyle` opacity, `getAnimations()[0].currentTime`,
   projected rects) or temporarily bump a duration constant and slow-sample. (Now in `CLAUDE.md`.)
2. **`RecidexLibrary.snapshot()` via a bare `setTimeout`** captured a mid-morph (tiny, rotated) card
   rect when rAF was behind. Fixed by making `exitToRecipe` resolve on `anim.raw >= 1` **and**
   computing the rect analytically through `_projCam` (fixed `CAM_RECIPE`) rather than reading the
   live mesh/camera.
3. **`toDataURL` on the WebGL canvas returns blank** without `preserveDrawingBuffer: true` (R3F clears
   the buffer each frame). It's set on the `<Canvas>` `gl` prop now (small perf cost, fine here).
4. **Programmatic `.focus()` doesn't match `:focus-visible`** → the default UA outline showed on the
   auto-focused Cancel button. Added `.gen-danger .pill:focus{outline:none;box-shadow:inset 0 -2px 0 0 var(--orange)}`.
5. **`CenterPreview` "fly the hovered card to center"** (an earlier iteration) moved the click target
   while the user was reaching for it. Reverted to a fixed-position **duplicate**; the original never
   moves.
6. **Card tangent sign:** `angle + 90°` put the readable faces on the back arc; `angle − 90°` puts
   them on the near/side arcs. Use `−`.
7. **`.rv-stage` width 0** under `justify-items:center` in the `<1040px` layout (positioned children
   contribute nothing to a shrink-wrapped grid item) — needs an explicit `width` in that media query.
8. **Full R3F library screenshots occasionally hang** if esm.sh is slow to serve the modules (40s
   `waitForFunction` timeout → 2min command timeout). Transient; retry, or use `screenshot.mjs`
   (short wait, no `waitForFunction`).
9. Pre-existing: throwaway `.mjs` tests must live in the **project root** (not `/tmp`) to resolve
   `puppeteer-core`; target the "Save changes"/"Generate" button **by text** (two `.pill.red` in the DOM).
